# 产品演示与 README 截图

README 是面向玩家与说书人的产品入口；具体操作见[操作手册](USER-GUIDE.md)。此文档记录如何保持展示内容与应用一致。截图分别用于 README 和操作手册。

## 一条命令重建

```bash
npm ci
npx playwright install chromium
npm run dev
# 在另一个终端执行
npm run demo:screenshots
```

默认访问 `http://127.0.0.1:5173/`。也可以指定生产预览地址：

```bash
npm run build
npm run preview
DEMO_BASE_URL=http://127.0.0.1:4173/botc-script-editor/ npm run demo:screenshots
```

浏览器与页面在每次运行结束时关闭，包括失败时。失败会返回非零退出码，不能将部分输出视为完整生成成功。

## 固定演示数据

数据源为 `scripts/demo-data.mjs`：十名虚构玩家、暗流涌动剧本、7 镇民 / 2 爪牙 / 1 恶魔、恶魔伪装、提名与私密行动示例，以及十二场虚构历史记录。时间与结果固定，便于比较不同版本的截图。

脚本在新建的隔离浏览器中写入演示存档，跳过首次引导；不会修改个人浏览器数据，不会发起在线入座、发牌或消息请求。README 明确说明记录、评分和胜率为演示数据。

## 发布前维护

1. 用当前代码重新生成全部七张截图，逐张检查；尤其不能把加载画面当成内容。
2. 检查 README 中每个本地链接与图片路径，预览桌面和手机排版。
3. 如界面文字变化，更新脚本中的可访问名称选择器；不可用静默跳过来隐藏失败。
4. 更新 `docs/CHANGELOG.md`，区分本次新增、修复与已有能力的文档补齐。
5. 主持流程变化时运行相关端到端测试；本次回归使用 `e2e/script-apply.spec.ts`，覆盖未应用、改回原选项、关闭重开、应用、角色保留及刷新后持久化。

在线认领、消息与 AI 服务并非此截图流程的联机验证范围。桌面安装包与 Android 包也不由该脚本构建。

## 玩家操作图解：本地模拟在线会话

保持 Vite 开发服务器运行，再执行：

```bash
npm run demo:players
```

这个命令需要开发服务器，不能使用生产预览。它通过浏览器请求拦截，将 `DealSession` 服务替换为 `scripts/demo-deal-service.mjs`，并阻止 Firebase 网络请求。真实 React 界面和按钮处理逻辑保持不变，服务数据仅保存在隔离浏览器中，不会创建线上房间、发送真实角色或消息。

脚本操作主持人与玩家两个页面：创建演示入座会话、点击空座位、输入姓名、确认认领、由主持人点击发送角色、玩家打开身份卡，再点击投票。提名通过模拟服务准备；截图中的倒计时时间固定，便于重现。
