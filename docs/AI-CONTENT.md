# AI 助手的本地资料：盘点、知识缺口与数据格式

日期：2026-09-24。配合 [AI-ARCHITECTURE-OFFLINE-FIRST.md](AI-ARCHITECTURE-OFFLINE-FIRST.md) §15–§19。覆盖表由 `node scripts/audit-ai-content.mjs [--online]` 生成，数据更新后重跑即可。

## 1. 结论

- **最大缺口已补：** 之前只有奥德赛有“怎么玩 / 举例 / 技巧 / 伪装”资料，官方与中文版角色只能给能力原文，小模型随后自己编。现在从集石 wiki（中文，229 个角色）和官方英文 wiki（181 个角色）导入角色攻略，与奥德赛年鉴同一格式，按问题意图选节、按运行时控制长度、每条附来源页。
- **路由：** 问题意图（范例 / 伪装 / 对抗 / 主持 / 怎么玩 / 简介 / 规则细节）由 `guideIntent` 判断；以前的 `ASKS_GUIDE` 正则只认前四种，“怎么主持”“水手被处决会死吗”拿不到角色资料。
- **提示词预算：** 以前攻略塞在目录块的 1,500（本地）/ 1,900（在线）估算 token 里，被裁到一两句；现在攻略单独成块（本地 700 字、在线约为输入预算的 30%，上限 1,600 字）。
- **术语：** 注入每个提示词的译名表有十余处不是官方中文（克制关系、提示牌、好人阵营、第一夜、亡魂票、登记为……），已按集石术语汇总改正；另加 12 组玩家说法 → 规则用词的检索别名（鬼票、首夜、醉着……）。
- **Wiki 摘录：** 中文页按空格计词，整页只切出 1–3 块（最大 5,840 字）；目录被当成正文；同级标题被当成父标题。已修，块数 67 → 257，中文最大块 990 字，术语表一词一块。
- **新鲜度：** 攻略页面与 wiki 当前修订一致。能力文本与官方来源的差异（英文 18、中文 49）已分类并加了官方修订（63 个角色，原文保留为旧修订）；本地山雨欲来停在 2025 年底，已按集石 2026-07/08 新版更新 9 个角色（§3.1）。

## 5. 攻略数据格式

一种格式覆盖所有版本（类型见 `src/core/ai/guides.ts`）：

```jsonc
// assets/almanac/<edition>.<lang>.json
{
  "schema": 1, "edition": "bmr", "language": "zh",
  "name_zh": "黯月初升", "name_en": "Bad Moon Rising",
  "source": "https://clocktower-wiki.gstonegames.com/", "source_name": "钟楼百科（集石，官方中文 wiki）",
  "license": "No license stated by the site; © the publisher. …", "fetched": "2026-09-24",
  "terminology": { },                      // 只有角色包自己的术语（奥德赛）
  "characters": {
    "sailor": {
      "source": "https://…?title=%E6%B0%B4%E6%89%8B", "revid": 6479,
      "ability": "每个夜晚，你要选择……",   // 这份攻略依据的能力文本
      "summary": "段落\n\n段落", "howto": "…", "examples": "…", "rules": "…",
      "reminder_details": "醉酒\n放置时机：…\n移除时机：…",
      "tips": "…", "bluffing": "…", "fighting": "…", "flavor": "…",
      "tags": ["免死", "醉酒"]
    }
  }
}
```

- **节 id 统一：** `summary`（角色简介 / Summary）、`howto`（运作方式 / How to Run）、`examples`（范例 / Examples）、`rules`（规则细节）、`reminder_details`（提示标记，一个标记一段）、`tips`（提示与技巧 / Tips & Tricks，“作为善良 / 作为邪恶”写在段首）、`bluffing`（伪装成… / Bluffing as…）、`fighting`（对抗… / Fighting…）、`flavor`（背景故事）。集石页面是英文 wiki 的翻译，两种语言同一角色同一节可以对齐。奥德赛年鉴原本就用这些字段名，另有 `design_notes`、`credits`、`night` 等，读取方忽略。
- **段落是最小单位：** 节内段落用空行分隔，检索排序和长度预算都按整段取舍，只有第一段超长时在句末截断。
- **每语言一个文件、每版本一个 chunk：** 只加载问到的版本和语言；缺某语言时回退另一语言，并标明。部分翻译（奥德赛英文）按节回退：本语言攻略没有问题要的节（`guideCovers`）时用另一语言的。翻译文件带 `translation` 块，条目带 `translated_from`，回答里标“unofficial community translation”。
- **清单 `assets/almanac/index.json`（约 12 KB，打进主包）：** 每个文件的版本、语言、来源、日期、字节数、术语数、角色 id。用来同步判断“这个角色有没有攻略”（角色详情面板只在有攻略时显示）、“这个版本有没有术语表”（以前按“有没有年鉴文件”判断，加入官方攻略后会误判，还会让每次提问都加载全部文件）。`src/__tests__/guides.test.ts` 检查清单与文件一致。
- **长度：** `GUIDE_BUDGET` 本地模型 700 字 / 无模型回答 900 字 / 在线 1,600 字（每题最多两个角色平分；英文按 2.5 倍字符）。本地 4K 模型的提示词（`水手这个角色怎么玩`）实测在 `WEBLLM_INPUT_BUDGET − 400` 以内；Groq 在 5,500 − 200 以内。
- **意图 → 节：** 举例 → examples；伪装 → bluffing；对抗 → fighting + tips；主持 → howto + reminder_details；怎么玩 → summary 首段 + tips（无 tips 时 summary + examples）；介绍 → summary；规则细节（会不会、如果、被处决、醉酒……）→ rules / summary / howto / examples 中与问题最相关的段落。
- **追踪：** 回答 trace 新增 `guides`（给了哪些角色的攻略），反馈报告的“检索缺口”也计入它；`PROMPT_VERSION` 升到 `2026-09-24.2`。

`src/core/ai/guides.ts` 不依赖框架；Worker 的目录快照（`coreCatalog.test.ts`）不含攻略，未受影响。

## 6. 规则资料的检索质量

- **切块（`scripts/wiki-chunk.mjs`）：** 长度按“英文词 + 汉字 / 2”计算，上限 350；删除目录节；标题链按层级（以前同级的上一个标题被当成父标题，如“Gather Your Players › Prepare The Grimoire”）；术语表每个词条一块、标题就是词条名，“被当作是什么意思”直接命中该词条。
- **别名（`expandTermAliases`）：** 规则检索（Web 与 Worker `search_rules`）先把玩家说法补上规则用词：鬼票 / 死人票 → 死亡玩家 投票 一次；首夜 → 首个夜晚；醉着 → 醉酒；登记 ↔ 被当作；好人 / 坏人 → 善良 / 邪恶……
- **官方中文用词：** 译名表改为集石术语（相克规则、被当作、首个夜晚、其他夜晚、投票标记、提示标记、角色标记、善良阵营、与之邻近的玩家、初始设置、魔典、流放……）；核心规则写作“被当作”（也常说“登记为”），补了“清醒 / 健康”和“每局游戏限一次在醉酒时也算用掉”。
- **双语对齐：** 中英 wiki 页面按主题成对（rules ↔ zh-rules、glossary ↔ zh-glossary、st-advice ↔ zh-st-tips、states + abilities ↔ zh-details），检索按语言过滤（`page` 前缀 `zh-`）。没有做块级对齐：两边的页面结构不同，对齐收益小于维护成本。

## 7. 维护

| 命令 | 作用 |
|---|---|
| `npm run build:guides` | 从两个 wiki 生成攻略与清单（页面缓存在 `node_modules/.cache/build-guides/`；`-- --refresh` 重新抓取；`-- --lang zh` 只做中文） |
| `node scripts/build-guides.mjs --index-only` | 手改某个攻略文件（如奥德赛年鉴）后重建清单 |
| `node scripts/audit-ai-content.mjs --online` | 本文的覆盖表 + 与官方来源对比 |
| `npm run build-wiki` | 重建 `public/wiki-chunks.json` |
| `npm run sync-reminders` | 提示标记对照（同时留下 `roles.json` 缓存供审计用） |
| `npm run check-abilities` | 能力文本与官方来源的差异及分类（先跑上面两个生成缓存） |
| `npm run add-revision -- <id> --en … --zh … [--revision v2026-09] [--note …] [--keep-current]` | 给单个角色加修订 |

集石 wiki 对自称爬虫的 User-Agent 返回 403，脚本用 Node 默认 UA；英文 wiki 用带说明的 UA。两个站都没有声明内容许可，攻略按条目保留来源链接，与 `wiki-chunks.json` 的做法一致。集石缺页的中文角色改用 B 站社区 wiki（BWIKI）：目前补上刀客、史官，条目标 `community: true`，回答与年鉴面板标明“社区 wiki，非官方”。民间角色与剧本的导入方案见 [COMMUNITY-CONTENT.md](COMMUNITY-CONTENT.md)。

## 8. 剩余缺口

1. **待确认的版本：** 戏子 / 禁卫军的默认修订；山雨欲来已退出测试名单的 8 个角色是否保留（§3.1）。
2. **缺少的角色：** 传奇“赦令承旨”（山雨欲来）、“麒麟”（华灯初上）。
3. **中文版相克：** 华灯初上 / 山雨欲来与官方角色的相克（如戏子与间谍、打更人与利维坦）只在 wiki 文本里，`jinxes.json` 没有，程序的相克回答与剧本校验用不到。
4. **缺页：** 刁民和山雨欲来 6 个角色（风水师、染坊坊主、书童、阎罗、偃师、俑匠）两个 wiki 都没有页面；中文版、传奇、奇遇没有“提示与技巧 / 伪装”。
5. **英文：** 中文版没有英文攻略；奥德赛的英文（能力、标记、夜晚提示、年鉴四节与术语）是社区翻译，待作者审阅（[ODYSSEY.md §4.1](ODYSSEY.md)），运作方式与规则细节未译。
6. **民间内容：** B 站 wiki 的民间角色（数千个）与钟楼博物馆的剧本尚未导入，方案见 [COMMUNITY-CONTENT.md](COMMUNITY-CONTENT.md)。
7. **MCP：** Worker 没有攻略工具；托管在线模式靠前端把攻略放进提示词，外部 MCP 客户端拿不到。可加 `get_character_guide`（数据需进 Worker 包，约 3 MB，或按需从静态站点读取）。
8. **剧本级与局势策略：** 按剧本的攻略、更多版本的局面规则仍靠通用建议。
9. **路由是正则：** 意图判断（`guideIntent`）与俚语别名是启发式的；按反馈里 `guides` 为空的 👎 调整。
10. **在线评测未跑：** 新增的 9 题（`guide-*`、`term-ghost-vote`）离线全部通过；托管模型上的效果需 `BOTC_AI_EVAL_URL=… BOTC_AI_EVAL_ONLY=guide npx vitest run src/__tests__/aiEval.live.test.ts`。
